# Older-version export regressions

These inputs were created or refreshed with native KiCad 10.99 readers and writers,
then opened and saved in the native editors on 2026-10-08 or 2026-10-09. Item
identifiers come from KiCad's KIID generator. The explanatory annotations were
reviewed and edited in KiCad. These are regression inputs, not expected files
generated by the exporter.

| Fixture | Regression and expectation |
| --- | --- |
| `project_barcode/` | The QR code uses the project variable `${SERIAL}`. A changed project value must take priority over an older cached board property. Export to KiCad 9 must produce the same polygons as a literal-value barcode. |
| `bus_alias_connectivity/` | `Bus1` is defined in the companion project as `D[0..7]`, `CTL1`, and `CTL2`. A standalone KiCad 10 schematic export must retain that definition and all ten J1–J2 signal pairs. |
| `embedded_files/` | A custom drawing sheet is embedded in the schematic. Both frozen writers must retain its exact payload even without optional root-instance bookkeeping. Child sheets must not duplicate the shared payload. |
| `group_placement/` | Four placement rule areas link to groups. KiCad 9 drops only those links, while KiCad 10 keeps them. Both targets retain the zones, groups, copper, and explanatory board text. |
| `tuning_model_settings/` | A 5 GHz, solder-mask-aware profile is compared with a default 1 GHz profile. Export to KiCad 10 must report the two non-default setting losses and require approval. Default settings add no losses. |

The embedded worksheet comes from the existing native drawing-sheet fixture
`qa/data/cli/basic_test/custom_ds.kicad_wks`. The bus-alias design derives from
`qa/data/eeschema/netlists/prefix_bus_alias`. The barcode and tuning boards were
created with the native PCB model and writer before their GUI review.
