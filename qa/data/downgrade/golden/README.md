  keepouts in **board coordinates**; pads, drilled pads, graphics, mirrored text,
  stable UUIDs, nets, tracks, a via, a board zone, origins and mask settings.
- `graphics`: hatched fills and knockout text boxes kept for 10, independently

  report as well as the exported file.
- `v9/graphics-drop`: the independently authored `seed/graphics-drop-v9` saved

- `body_styles`: selected third custom style, common pins, another instance using

- `rules`: quotes, parentheses and unsupported-looking tokens in real full-line

## Comparison contract

PCB and v10 schematic comparisons parse the complete s-expression tree. They do
not ignore UUIDs, versions, nets, attributes, item ordering, sizes or settings.
Only these differences are allowed:

- Whitespace and integer/decimal spelling of the same number.
- The root `generator_version` metadata.
- `pngdpi`/`pngantialias` in PCB plot settings: neither target has PNG plot output.
- The obsolete KiCad 9 plot options **only at their default values**:
  `hpglpennumber=1`, `hpglpenspeed=20`, `hpglpendiameter=15`, `plotinvisibletext=no`.
  Missing entries load to those same defaults; non-default values are not ignored.
- At most **2 nm** of XY-coordinate rounding during affine/legacy conversions.
  This tolerance does not apply to dimensions, angles, clearances or other settings.

The v9 schematic compares active drawings, positions, orientations and pin UUIDs
against the separately authored design, and every `(reference, pin)` connection,
net class, pin function and electrical type against the native v9 netlist. For
this comparison only, the v9 reference pin function is normalized from `name` to
`name_number`, matching the newer netlist writer's notation; raw pin names are
also checked directly. Netlist timestamps, source filenames, generated net codes
and cache-symbol names are not electrical design data. DRC references are compared
byte-for-byte and parsed.

The comparator has negative tests proving it rejects changed coordinates, pad
sizes, nets, angles, clearances and version stamps.

## Regeneration

Work in a scratch directory. Use actual release binaries/modules, not this
branch's frozen writers. For 9, whose CLI has no upgrade command:

```sh
"$KICAD9_PYTHON" generate_native_board.py --major 9 seed/geometry.kicad_pcb scratch/geometry.kicad_pcb
"$KICAD9_PYTHON" generate_native_board.py --major 9 seed/graphics-v9.kicad_pcb scratch/graphics.kicad_pcb
"$KICAD9_PYTHON" generate_native_board.py --major 9 seed/graphics-drop-v9.kicad_pcb scratch/graphics-drop.kicad_pcb
```

The helper creates a wx application and verifies that each saved board reloads
with the same item UUIDs. Use the release's bundled Python, pcbnew and wx modules
in a graphical session. Existing valid UUIDs are retained by default.

For a deliberate identity refresh, add `--uuid-map scratch/pcb-uuids.json` to
the native Python commands, using `--major 10` with KiCad 10's Python. Missing
entries are allocated by KiCad's random `KIID` generator. Reuse that same map
for every matching seed and reference, including the drop-policy design, and
apply it to the current inputs before saving them with the ordinary current
writer. Do not refresh individual goldens independently, because item identity
is part of the comparison contract. Keep the mapping as a regeneration artifact
outside the repository.

For 10, copy the appropriate seed to scratch and run its native CLI:

```sh
"$KICAD10_CLI" pcb upgrade --force scratch/geometry.kicad_pcb
"$KICAD10_CLI" pcb upgrade --force scratch/graphics.kicad_pcb
"$KICAD10_CLI" sch upgrade --force scratch/body_styles.kicad_sch
"$KICAD10_CLI" sch export netlist --output scratch/body_styles.net scratch/body_styles.kicad_sch
```

Use `geometry.kicad_pcb`, `graphics-v10.kicad_pcb`, `body_styles-v10.kicad_sch`
and `body_styles.kicad_pro` as the 10 seeds. Use `body_styles-v9.kicad_sch` as
`scratch/body_styles.kicad_sch` for the native 9 netlist command. Open each
schematic with its native schematic editor and use **Save As** to force a complete
save, including the root sheet records and project settings. Keep the filename
`body_styles.kicad_sch` and its matching project file in every scratch directory
so the symbol instance project name remains `body_styles`.

For a deliberate schematic identity refresh, allocate UUIDs with KiCad's `KIID`
generator and reuse one mapping across the seeds, current input, native references
and project hierarchy records. Update the root paths and pin IDs too, then save
with each corresponding native editor and regenerate both release netlists. The
CLI policy tests must use the same refreshed U1 identity. Retain the mapping as
an artifact outside the repository. Preserve intentional corruption in negative
fixtures and keep DRC text references independent and byte-exact.

Generate current inputs with the **normal** 10.99 writers from the same independent
seeds. Inspect changes before replacing checked-in references.

## Running

No installed KiCad 9/10 or network access is needed by the automated tests:

```sh
qa_pcbnew --run_test=BoardDowngrade,DowngradeOracle
qa_eeschema --run_test=SchDowngrade,SchDowngradeOracle
```

Native-reader validation remains valuable when adding a new golden, since the
current reader alone cannot prove what an older release will do.

The token-oracle suites also construct feature-rich current-version designs and
export each to **9.0 and 10.0**, with approximation enabled and disabled. These
are grammar tests, not golden references. Independent release keyword lists
check the exported output, while explicit report expectations ensure the inputs
exercise all 23 non-blocking PCB rules and all 11 non-blocking schematic-screen
rules where the target predates them. Coverage includes footprint graphics,
custom pad primitives, cached symbol graphics, custom body-style baking and
fractional-PPI image scaling. The tests require a lossy report, reload the result
to check transformations, and verify the source is unchanged. The PCB reload
check accounts only for the current reader reconstructing explicit false via
protection flags from legacy files, with every reconstructed flag checked OFF.

`BoardZoneDefaultsRoundTripAndDowngrade` additionally pins board-level hatch
offsets through current-version loading and export. These must load into the same
board-settings map used by the writer, remain intact for 10.0, and be reported
and removed for 9.0 rather than silently disappearing before classification.

Release-specific tests resolve targets by stable IDs, never by catalog position.
Adding a newer target cannot silently redirect the 9.0/10.0 comparisons.

The CLI policy tests cover checked/unchecked export, preview and JSON report
agreement, consent, local libraries, blockers and source-file preservation:

```sh
KICAD_CLI=/path/to/kicad-cli python3 -m unittest discover -s qa/tests/cli -p test_downgrade.py
```
